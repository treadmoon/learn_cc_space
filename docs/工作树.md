# Worktree 在本项目中的设计与运作

## 概述

Worktree 是 Git 的原生能力，允许从同一个仓库同时检出多个分支到不同目录。本项目将此能力封装为 `WorktreeManager`，作为 Agent 基础设施层的一部分，提供给 LLM Agent 作为可调用工具，同时在前端以结构化卡片展示。

## 核心价值

### 解决什么问题

在多 Agent 协作场景中，多个 Agent 可能需要同时操作同一个代码仓库：

- 主 Agent 在 main 分支开发功能 A
- 子 Agent 需要同时在 feature 分支修 bug
- 后台任务需要在独立分支跑测试

如果所有 Agent 共享同一个工作目录，会产生文件冲突和状态污染。Worktree 让每个 Agent 拥有独立的工作目录，同时共享同一个 `.git` 仓库。

### 与传统方案对比

| 方案 | 优点 | 缺点 |
|------|------|------|
| `git clone` 多份 | 完全隔离 | 浪费磁盘，`.git` 不共享 |
| `git stash` 切换 | 省空间 | 不能并行，容易丢 stash |
| **`git worktree`** | 共享 `.git`，独立工作区，可并行 | 分支不能重复检出 |

## 组件详解

### 1. WorktreeManager（后端核心）

**文件**: `src/lib/agent/managers.ts`

单例模式，通过 `globalForAgent` 确保 Next.js HMR 不会重复实例化。

#### WorktreeInfo 接口

```typescript
interface WorktreeInfo {
    path: string;    // worktree 绝对路径，如 /Users/meil/codeSpace/learn_cc_space-feature
    branch: string;  // 分支名，如 "feature"（已去除 refs/heads/ 前缀）
    head: string;    // 短 commit hash，如 "ad6da9a"
    bare: boolean;   // 是否 bare worktree（无工作区，只有 .git）
    locked: boolean; // 是否被锁定（通常因为目录不存在或被其他进程占用）
    isMain: boolean; // 是否为主 worktree（path === process.cwd()）
}
```

#### listStructured() — 解析 porcelain 格式

执行 `git worktree list --porcelain`，输出格式：

```
worktree /Users/meil/codeSpace/learn_cc_space
HEAD ad6da9a feat: add internationalization support
branch refs/heads/main

worktree /Users/meil/codeSpace/learn_cc_space-feature
HEAD 73a7c26 Initial commit from Create Next App
branch refs/heads/feature-branch
```

解析逻辑：
1. 按空行分割每个 worktree 条目
2. 每行按首个空格分割为 key/value
3. `worktree` → path，`HEAD` → head（截取前 8 位），`branch` → 去除 `refs/heads/` 前缀
4. `bare` / `locked` 为布尔标记（无 value）
5. 最后一个条目无尾部空行，需额外提交

#### create() — 创建 worktree

```typescript
create(branch: string, worktreePath?: string): string
```

- 执行 `git worktree add <path> <branch>`
- 若不指定 path，自动生成：`../<repo>-<branch>`
- 返回确认消息或错误信息

#### remove() — 删除 worktree

```typescript
remove(target: string): string
```

- 支持绝对路径或分支名
- 若传入分支名，先通过 `listStructured()` 查找对应 path
- 执行 `git worktree remove <path> --force`
- `--force` 允许删除有未提交更改的 worktree

### 2. Agent 工具（LLM 可调用）

**文件**: `src/app/api/chat/route.ts`

注册了 3 个工具，LLM Agent 可在对话中自主调用：

```typescript
// 查看所有 worktree
worktree_list()
// → 返回 JSON 数组，每个元素包含 path, branch, head, bare, locked, isMain

// 创建 worktree（为 feature 分支创建工作目录）
worktree_add({ branch: "feature-x" })
// → "Created worktree for 'feature-x' at /Users/meil/codeSpace/learn_cc_space-feature-x"

// 删除 worktree（支持分支名或路径）
worktree_remove({ target: "feature-x" })
// → "Removed worktree at /Users/meil/codeSpace/learn_cc_space-feature-x"
```

**工具路由**：在 `createToolHandlers()` 中，`worktree_list` 返回 JSON 字符串供 LLM 阅读，`worktree_add` 和 `worktree_remove` 直接调用 WorktreeManager 方法。

### 3. State API（前端轮询）

**文件**: `src/app/api/state/route.ts`

每 2 秒被前端轮询，返回结构化 worktree 数据：

```typescript
let worktrees: WorktreeInfo[] = [];
try { worktrees = WORKTREE_MGR.listStructured(); } catch {}
```

配合 ETag 条件请求，状态未变时返回 304 节省带宽。

### 4. 前端展示（LeftPanel）

**文件**: `src/components/LeftPanel.tsx`

工作树集群区域以卡片列表展示每个 worktree：

```
┌─────────────────────────────────────┐
│ 🌿 main                    [main]  │
│    /Users/meil/codeSpace/learn_cc   │
├─────────────────────────────────────┤
│ 🌿 feature-x                       │
│    /Users/meil/codeSpace/learn_cc-… │
├─────────────────────────────────────┤
│ 🌿 hotfix              [locked]    │
│    /Users/meil/codeSpace/learn_cc-… │
└─────────────────────────────────────┘
```

卡片元素：
- **图标颜色**：主 worktree 为绿色（`var(--color-success)`），其他为紫色（`var(--color-accent2)`）
- **分支名**：11px mono 粗体
- **路径**：9px mono 幽灵色，超长截断
- **标签**：`main`（绿色）、`locked`（琥珀色）、`bare`（灰色）
- **计数 badge**：Section 标题旁显示 worktree 总数

### 5. 页面状态管理

**文件**: `src/app/page.tsx` + `src/hooks/useGlobalState.ts`


## 典型使用场景

### 场景 1：Agent 并行任务

```
用户: "帮我同时开发 feature-A 和 feature-B"

主 Agent:
  1. worktree_add({ branch: "feature-A" })  → 创建独立目录
  2. worktree_add({ branch: "feature-B" })  → 创建另一个独立目录
  3. spawn_teammate({ name: "agent-a", role: "在 feature-A worktree 中开发..." })
  4. spawn_teammate({ name: "agent-b", role: "在 feature-B worktree 中开发..." })

子 Agent A: cd 到 feature-A worktree，独立工作
子 Agent B: cd 到 feature-B worktree，独立工作

完成后:
  5. worktree_remove({ target: "feature-A" })
  6. worktree_remove({ target: "feature-B" })
```

### 场景 2：热修复 + 功能开发并行

```
用户: "main 分支有个紧急 bug 要修，同时我不想中断当前的功能开发"

Agent:
  1. worktree_add({ branch: "hotfix-123" })  → 创建 hotfix 目录
  2. 在 hotfix 目录中修复 bug、提交、推送
  3. worktree_remove({ target: "hotfix-123" })  → 清理
  4. 继续在主目录开发功能（无需 stash）
```

### 场景 3：代码对比

```
用户: "对比 main 和 feature 分支的差异"

Agent:
  1. worktree_list()  → 确认 feature worktree 存在
  2. 在两个 worktree 中分别读取文件进行对比
  3. 输出 diff 结果
```

## 单例注册

WorktreeManager 通过 `globalForAgent` 模式确保单例：

```typescript
const globalForAgent = global as unknown as {
    // ...
    WORKTREE_MGR: WorktreeManager;
};

export const WORKTREE_MGR = globalForAgent.WORKTREE_MGR || new WorktreeManager();

// 开发模式: 挂回 global，HMR 时复用
if (process.env.NODE_ENV !== 'production') {
    globalForAgent.WORKTREE_MGR = WORKTREE_MGR;
}
```

这确保了：
- 首次加载时创建实例
- HMR 热更新时复用已有实例（不会丢失状态）
- 生产环境每次冷启动创建新实例
